# Safety Monitor

Локальная настольная программа для рабочих зон и видеонаблюдения.
Строгий классический интерфейс: меню, дерево зон слева, обзор камер,
таблица подключений и отдельные окна настроек.

Приложение запускается с пустым списком зон. Видео поступает только из
добавленных источников. Система анализа СИЗ пока не подключена; программа
сохраняет выбранные модули камеры, не генерируя детекции и нарушения.

## Запуск

Требуется Python 3.10+ с Tkinter. Проверено на Windows и Python 3.14.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

В этом рабочем каталоге `.venv` и зависимости уже подготовлены, поэтому
достаточно последней команды. При активированном окружении работает
обычный `python main.py`. Программа открывается сразу, без демонстрационного входа.

## Обучение модели на загруженном датасете

Отдельный файл `models.py` в корне проекта обучает детектор YOLO26n на
COCO-разметке из `data/train`, `data/valid` и `data/test`. В загруженном
датасете три класса: `Helmet` (каска), `No-Helmet` (голова без каски) и
`Person` (человек). Родительская категория `SAFETY` без объектов исключается.
Этот датасет не содержит разметки остальных модулей СИЗ.

Для обучения используйте Python 3.10+ и отдельные зависимости.
PyTorch и Ultralytics устанавливаются отдельно от зависимостей приложения.
Датасеты исключены из Git; разместите загруженные изображения и COCO-разметку
в `data/train`, `data/valid` и `data/test`.
Подготовка датасета доступна без установки зависимостей обучения:

```powershell
.\.venv-local\Scripts\python.exe models.py --prepare-only
```

Окружение `.venv-local` с Python 3.12 используется настольным приложением.
Обучение требует отдельной установки зависимостей из `requirements-training.txt`
и CUDA-сборки PyTorch. Можно использовать другое окружение Python 3.10+,
заменив путь к интерпретатору в примерах ниже.

Для YOLO26 требуется Ultralytics 8.4.0 или новее; версия указана в
`requirements-training.txt`. При первом обучении стандартные веса
`yolo26n.pt` скачиваются автоматически;
для работы без интернета укажите уже загруженный файл через `--model`.

По умолчанию выбран компактный вариант `n`. Более крупные варианты
`yolo26s.pt`, `yolo26m.pt`, `yolo26l.pt` и `yolo26x.pt` задаются через `--model`.
Они требуют больше вычислительных ресурсов. Точность на вашем датасете
следует сравнивать по validation; окончательную оценку выполняйте на test.
Описание вариантов и результаты на COCO доступны в
[документации YOLO26](https://docs.ultralytics.com/models/yolo26/).

Подготовка создаёт `data/yolo/dataset.yaml`, нормализованные метки и списки
изображений с сохранением исходного разделения train/valid/test. Исходные
JSON и изображения сохраняются. Изображения подключаются жёсткими ссылками
или копируются, если ссылки недоступны. Файлы в `data/yolo/images` следует
использовать только для чтения, поскольку ссылка указывает на исходное изображение.
Короткие имена в подготовленном датасете обходят ограничение длины пути Windows.
Рамки обрезаются по границам изображения; вырожденные рамки пропускаются.
Отсутствующие изображения и статистика записываются в
`data/yolo/preparation_report.json`. Для остановки при отсутствующих файлах
добавьте `--strict`. Подготовка не требует установки Ultralytics или PyTorch.

Настройки по умолчанию подобраны как стартовая конфигурация для обнаруженной
RTX 3050 Laptop с 4 ГБ VRAM: YOLO26n, размер изображения 640, CUDA GPU 0,
AMP (смешанная точность), seed 42 и два процесса загрузки данных.
`batch=-1` включает AutoBatch с целью использовать примерно 60% видеопамяти;
фактический размер batch выводится в консоль. Ранняя остановка отключена
(`patience=0`), чтобы использовать заданный бюджет времени.

`--time-hours 2` установлен по умолчанию и передаёт Ultralytics лимит обучения
в два часа. Он имеет приоритет над количеством эпох: число эпох определяется
по фактической скорости обучения. Подготовка и сканирование данных, загрузка
весов, финальная валидация и сохранение результатов добавляют время к этому
лимиту. Поэтому весь запуск может длиться немного дольше двух часов.
Настройки не гарантируют наилучшую точность: её оценивают по метрикам validation.

Изменить бюджет времени или вернуться к фиксированному числу эпох:

```powershell
.\.venv-local\Scripts\python.exe models.py --time-hours 2 --device 0
.\.venv-local\Scripts\python.exe models.py --time-hours 0 --epochs 100 --batch 8 --patience 20
.\.venv-local\Scripts\python.exe models.py --time-hours 0.02 --workers 0
```

Код рассчитан на CUDA-сборку PyTorch. Отдельный CUDA Toolkit для готовой
сборки не требуется; необходим совместимый драйвер NVIDIA.
После установки PyTorch подключение GPU проверяется так:

```powershell
.\.venv-local\Scripts\python.exe -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"
```

Если CUDA недоступна, запуск с настройками по умолчанию завершится с ошибкой.
Для явного выбора CPU используйте `--device cpu --batch 4`; автоматический
выбор устройства доступен через `--device auto`. При нехватке оперативной
памяти или проблемах DataLoader на Windows установите `--workers 0`.
Инструкции по сборкам CUDA доступны на [сайте PyTorch](https://pytorch.org/get-started/locally/).

Результаты сохраняются в `runs/detect/ppe/`: лучшие веса — `weights/best.pt`,
последняя эпоха — `weights/last.pt`, метрики — `results.csv` и графики.
При повторном запуске Ultralytics создаёт следующую папку (`ppe2` и т. д.);
точный путь к лучшим весам выводится в консоль.
Validation используется во время обучения, а `--evaluate-test` отдельно
оценивает лучшие веса на test после его завершения.

Продолжить прерванное обучение можно после сохранения хотя бы одной эпохи:

```powershell
.\.venv-local\Scripts\python.exe models.py --resume runs/detect/ppe/weights/last.pt
```

При продолжении параметры обучения восстанавливаются из checkpoint.
Обученные веса пока не подключаются к видеоинтерфейсу автоматически.
API обучения и формат меток описаны в
[документации Ultralytics](https://docs.ultralytics.com/modes/train/).

## Подключение IP-камеры

1. Слева нажмите **Создать…**, задайте название рабочей зоны.
2. Нажмите **Добавить камеру…**.
3. Укажите название и выберите **IP-камера (RTSP)**.
4. Введите полный RTSP-адрес потока вашей камеры, например по шаблону:

   ```text
   rtsp://USER:PASSWORD@192.168.1.50:554/STREAM_PATH
   ```

5. Выберите транспорт **TCP** или **UDP** и сохраните камеру.

`USER`, `PASSWORD`, адрес и `STREAM_PATH` заменяются параметрами вашей камеры.
Точный путь берётся из документации или веб-интерфейса производителя.
Камера должна быть доступна с компьютера, а RTSP — включён в её настройках.
Специальные символы в логине/пароле требуется кодировать для URL.

По умолчанию камеры подключаются при открытии зоны. Это поведение можно
отключить в **Настройки → Настройки приложения**. Кнопки **Подключить** и
**Отключить** работают с выбранной камерой; если выбрана сама рабочая зона,
они применяются к камерам текущей страницы.

При недоступности RTSP показывается состояние ошибки и выполняется повторное
подключение (по умолчанию через 5 секунд). Демонстрационное изображение не подставляется.
Настроены таймауты открытия 5 секунд и чтения 3 секунды для FFmpeg.
Параметры таймаутов передаются при открытии захвата, как предусмотрено
[API OpenCV](https://docs.opencv.org/4.x/d4/d15/group__videoio__flags__base.html).

Также поддерживаются USB-камеры по индексу устройства и локальные видеофайлы.
Видеофайл повторяется после окончания, изображение сохраняет исходные пропорции.

## Рабочие зоны и камеры

- Создание, открытие, переименование и удаление зон через левую панель и меню **Файл**.
- Дерево камер внутри каждой зоны и отдельная вкладка **Камеры** с таблицей.
- Добавление, изменение подключения и удаление камер через панель инструментов
  или меню **Камеры**. Двойной щелчок по строке таблицы открывает свойства.
- Контекстное меню таблицы для подключения и настройки выбранной камеры.
- Обзор в 1, 2 или 3 колонки; на узком окне количество колонок уменьшается.
- До 9 камер на странице. Потоки других страниц закрываются; переходы доступны
  кнопками **Назад / Далее**. Выбор камеры в дереве/таблице открывает её страницу.
- Настройки оформления: светлая, тёмная и системная темы.
- Горячие клавиши: **Ctrl+N** — создать зону, **Ctrl+O** — открыть зону.

## Модули СИЗ

Выберите камеру и откройте **Модули СИЗ…**. Настройки представлены отдельными
строками с обычными флажками:

- Каска.
- Сигнальный жилет.
- Защитные очки.
- Перчатки.
- Защитная обувь.
- Респиратор.
- Защита слуха.

Каждая камера хранит собственный набор модулей. Флажки задают конфигурацию
для будущего подключения модели; фактический анализ изображения сейчас не выполняется.

## Сохранение и закрытие

Рабочие зоны, адреса, модули и оформление автоматически сохраняются в
`data/config.json`. Запись атомарная; при ошибке сохраняется предыдущий файл
и отменяются изменения в памяти. Нечитаемый файл настроек не перезаписывается.
Сохранённый видеофайл, который был перемещён или удалён, не мешает запуску программы.

RTSP-адрес вместе с введёнными учётными данными хранится в локальном файле
конфигурации. В таблице источников логин, пароль и query-параметры скрыты.
Файл конфигурации исключён из Git.

Для другого файла настроек:

```powershell
.\.venv\Scripts\python.exe main.py --config "D:\Settings\safety.json"
```

Каждый видеопоток читается отдельным фоновым потоком. Он же выполняет
`VideoCapture.release()` в `finally`; интерфейс обновляется через `after()`
в основном потоке. Отмена подключения очищает старое изображение, а закрытие
окна останавливает захваты и отменяет обновления интерфейса.
При зависании нативного USB-драйвера поток сможет освободить устройство
после возврата из вызова драйвера; суммарное ожидание закрытия ограничено 6 секундами.

## Проверки

Без открытия окна и обращения к реальной камере:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip check
```

Интеграционная проверка кратковременно открывает окно и использует временную
конфигурацию и видеофайл. Она проверяет меню, диалоги, настройки модулей,
темы, DPI, таблицу, страницы камер, переключение зон и закрытие потоков:

```powershell
.\.venv\Scripts\python.exe -m tests.gui_smoke
```

На Windows снимки конкретного окна приложения сохраняются в `.artifacts`,
которая исключена из Git. Реальную IP-камеру можно проверить после ввода её RTSP-адреса.
