# Safety Monitor — контроль СИЗ

Настольное приложение для RTSP, USB-камер и видеофайлов. Исходные пять классов:
`PERSON`, `HELMET`, `VEST`, `GLOVES`, `PPE GLASSES`. Новое обучение добавляет
`NO HELMET`, `NO PPE GLASSES`, `NO GLOVES`, `NO VEST`; их рамки выделены красным.
Вкладка **Журнал событий** сохраняет фото, время, камеру, рабочую зону,
номер временного трека и перечень необнаруженных СИЗ.

## Подготовка нового COCO-архива (28 октября 2026)

Последний результат доразметки всех девяти классов находится в
**`data/ppe_full_annotation_review`** (1 830 изображений). Предложения СИЗ получены
двумя локальными помощниками; явные противоречия с исходными метками отложены
в `*_conflicts.json`. 357 новых предложений HELMET просмотрены на увеличенных
фрагментах: 94 исправлены на NO HELMET, 42 сомнительных/ошибочных удалены,
221 оставлено после проверки категории. Это не полная проверка всех объектов
на 1 830 изображениях: `training_ready` остаётся `false`.
Журнал исправлений — `visual_review_log.json`; актуальные количества —
`dataset_status.json` → `current_splits`. Предыдущие этапы сохранены.
`autolabel_ppe.py` и `autolabel_ppe.py --second-pass` воспроизводят проходы моделей;
после них `apply_visual_ppe_review.py` восстанавливает записанные визуальные исправления.
Карточки и источники помощников сохранены рядом с весами в `.artifacts/annotation-helper`.
Модели-помощники не заменяют рабочий `weights.pt`.

В `data/train`, `data/valid`, `data/test` находится PPE Combined v4. В нём
неполная разметка: `Person` есть примерно на 2,2% кадров и не размечен совместно
с нужными СИЗ. Прежний `data/construction-ppe` сейчас отсутствует.
`train90.cmd` использует `data/ppe_full_annotation_review` для пробного обучения.
Новые папки содержат **частично автоматическую разметку, требующую проверки**:

- `data/ppe_clean_review`: очищенная копия с девятью нужными классами, включая
  `NO VEST`. Полное декодирование JPEG, удаление точных дубликатов по пикселям,
  исключение отсутствующих файлов и кадров без целевой разметки. Исходники сохранены.
- `data/ppe_annotation_batch`: небольшая выборка с более равномерным количеством
  кадров разных классов для проверки/доработки разметки.
- В обеих папках `_annotations.coco.json` содержит исходные рамки и черновые
  предложения `PERSON`. Предложения помечены `annotation_source`, `score` и
  `review_status: unreviewed`. Доавтоматическая разметка сохранена рядом в
  `_annotations.before_person.coco.json`.
- `person_review_queue.csv` показывает кадры без найденного человека и с
  неуверенными автоматическими рамками. `dataset_status.json` содержит актуальные
  количества рамок и `training_ready: false`.

Помощник разметки — существующий `weights/yolo26n.pt`, используется только локально
для предложения рамок людей. Приложение по-прежнему использует **weights.pt**.
Авторазметка не исправляет все пропущенные СИЗ: перед обучением нужно проверить
все девять классов, а также разделить похожие кадры одной сцены между выборками.
Подозрительные группы перечислены в
`ppe_clean_review/possible_cross_split_near_duplicates.json`; это кандидаты,
а не доказанные дубликаты. Для пробного обучения подключена выборка
`ppe_full_annotation_review`; рабочие веса автоматически не заменяются.

Фотографии подключены жёсткими ссылками, где это возможно, чтобы не занимать
ещё несколько гигабайт. **Не изменяйте пиксели этих файлов**; JSON-разметка независима.
Удаление ссылки из новой папки не удаляет исходное фото из `data/train` и т. д.
Первоначальные атрибуция и лицензия скопированы в обе папки.

Скрипты: `prepare_ppe_review.py` создаёт новые папки (не перезаписывает существующие),
`autolabel_people.py` продолжает обработку по локальному SQLite-кэшу и обновляет
черновую разметку. Перезапуск не дублирует предложения людей.

## Быстрый запуск на этом компьютере

Рабочее окружение: `.venv-local`, Python 3.12, PyTorch с CUDA. Видеокарта:
NVIDIA RTX 3050 Laptop, 4 ГБ. Скрипты запуска сами выбирают это окружение;
системная команда `python` на этом компьютере указывает на старую версию 3.8.

1. Запустите **`run.cmd`**. В текущей конфигурации выбрана **model-v2**.
2. **Настройки → Выбрать модель…** (или кнопка в журнале) переключает модель для всех камер:
   - **model-v1** — прежняя модель, `weights/model-v1.pt`;
   - **model-v2** — новая модель из `weights1.pt`, `weights/model-v2.pt`.
3. Нажмите **Подключить** в окне выбора. Выбор сохраняется после перезапуска;
   статус показывает название модели и CUDA/CPU. Переключение сбрасывает результаты
   и отслеживание объектов предыдущей модели.
4. Откройте рабочую зону и подключите камеру. **Модули СИЗ…** задают обязательные СИЗ.

Обе версии — RF-DETR Small с девятью классами. Рядом с каждой находится
`model-v1.labels.json` / `model-v2.labels.json`, привязанная к SHA-256 весов.
Порядок ID взят из `args.class_names` самих checkpoint-файлов; служебный слот 9 исключён.
Исходные `weights/weights.pt` и `weights1.pt` сохранены.

Сравнение сохранённых отчётов обучения (не новый общий тест): mAP50–95
53,61% → 54,46%, precision 79,58% → 85,93%, recall 83,98% → 81,90%.
Рост среднего качества небольшой; качество отдельных классов различается.

Историческая информация об исходном экспорте до локального дообучения:

Карта классов лежит рядом: **`weights/weights.labels.json`** и привязана к SHA-256
конкретного файла. Названия предоставлены владельцем проекта Roboflow:
**1 GLOVES, 2 HELMET, 3 PERSON, 4 PPE GLASSES, 5 VEST**; слот 0 исключён.
Сдвиг ID проверен по совпадению рамок касок и жилетов с локальной разметкой.
Это другой порядок, чем у старого YOLO-датасета ниже.

Если карты нет, показываются рамки с числовыми ID без регистрации нарушений.
При несовпадении хэша загрузка останавливается с понятным сообщением.
Рамки рисуются на том кадре, который действительно обработан; частота
обновления размеченного видео зависит от скорости модели. Видеозахват продолжает
работать отдельно. После отключения камеры результаты сбрасываются.

Проверка исходного экспорта weights.pt на 60 локальных изображениях при пороге 0,25 дала
детекции HELMET и VEST, но не PERSON, GLOVES и PPE GLASSES. Это диагностическая
выборка, не полная оценка качества. Без уверенно найденного человека приложение
не регистрирует отсутствие СИЗ. Изменение подписей не улучшает обучение модели.

## Обучение weights.pt на 90 минут

1. Закройте приложение с камерами, подключите ноутбук к питанию и отключите сон
   на время обучения.
2. Запустите **`train90.cmd`**.
3. Дождитесь сообщения о завершении. Лимит тренировки — 90 минут; подготовка,
   последняя проверка и сохранение могут добавить время.
4. Новая модель и карта классов сохранятся в
   **`runs/rfdetr/<дата-время>-90min/weights.pt`** и **`weights.labels.json`**.
   Рабочая модель приложения автоматически не заменяется. После проверки результата
   для подключения нужны оба файла вместе.

Обучается именно RF-DETR Small на основе текущего `weights.pt`. Пять существующих
классов переносятся **по названиям**, четыре отрицательных класса обучаются по
аннотациям `data/ppe_full_annotation_review`. Всего 1 830 изображений:
1 311 train, 329 validation, 190 test. Порядок новых ID 0–8:
GLOVES, HELMET, PERSON, PPE GLASSES, VEST, NO HELMET, NO PPE GLASSES, NO GLOVES, NO VEST.
Последний служебный слот 9 игнорируется. Разметка частично автоматическая и содержит
пропуски, поэтому это пробное обучение; `training_ready: false` сохраняется.

Профиль для RTX 3050 4 ГБ: разрешение 512, batch 1, накопление градиента 8,
FP16, gradient checkpointing, workers 0, EMA; lr 0.0001, encoder lr 0.00001.
Выбор лучших весов выполняется на validation, test не участвует в обучении.
Полтора часа — ограничение времени, а не гарантия качества новых классов.
После обучения проверьте рамки на своих камерах, особенно очки и перчатки.

Каждый запуск создаёт отдельную папку **`runs/rfdetr/<дата-время>-90min/`**:
`run_config.json`, `dataset_report.json`, `result.json`, метрики, checkpoint,
`weights.pt` и `weights.labels.json`. Экспортированная модель проверяется через
тот же загрузчик, что в приложении. По умолчанию рабочие веса не меняются.
Флаг `--deploy` допускает замену только для датасета с `training_ready: true`
и положительным validation mAP; предыдущая пара файлов сохраняется в `previous/`.

Зависимости обучения на этом компьютере установлены. На новом компьютере после
обычного setup:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1 setup-training
# Только короткая проверка GPU; рабочие веса сохраняются:
powershell -ExecutionPolicy Bypass -File .\run.ps1 train --smoke --minutes 5
# Обучение с другим лимитом:
powershell -ExecutionPolicy Bypass -File .\run.ps1 train --minutes 90
```

## Параметры обучения

Все параметры собраны в `models.py`: `PROFILES` и `training_options()`.
Стартовый профиль `rtx3050` выбран для доступных 4 ГБ VRAM. Универсального
набора «максимально точных» параметров нет: качество оценивается после обучения.

| Параметр | Значение | Назначение |
|---|---|---|
| Модель | YOLO26n, предобученные веса | Компактная модель для ноутбука |
| Размер | 800 | Больше деталей мелких СИЗ, чем при 640 |
| Batch / workers | 4 / 0 | Запас VRAM; без задержек запуска процессов загрузки на Windows |
| Эпохи / patience | 120 / 25 | Остановка при отсутствии улучшения val |
| Оптимизатор / lr0 | AdamW / 0.001 | Явно заданная скорость обучения |
| weight_decay / lrf | 0.0005 / 0.01 | Регуляризация и конечная доля learning rate |
| Warmup / cosine LR | 3 эпохи / включён | Плавный старт и снижение шага |
| Mosaic / close_mosaic | 0.5 / 15 | Умеренная аугментация, отключение перед финишем |
| AMP / cache | включён / выключен | Меньше VRAM, без хранения датасета в RAM |
| Seed / deterministic | 42 / включён | Более воспроизводимый запуск |

Искусственный лимит в два часа убран. Лучшие веса выбираются по validation,
test не участвует в выборе эпохи. Test запускайте после окончательного выбора
профиля, например:

```powershell
.\.venv-local\Scripts\python.exe models.py --evaluate-test
```

Другие варианты:

```powershell
# Если доступна более мощная видеокарта: YOLO26s, 960, AutoBatch
.\.venv-local\Scripts\python.exe models.py --profile quality

# Меньше памяти / более быстрый эксперимент
.\.venv-local\Scripts\python.exe models.py --imgsz 640 --batch 2

# Продолжить именно новый пяти-классовый запуск
.\.venv-local\Scripts\python.exe models.py --resume runs\detect\ppe5\weights\last.pt

# CPU (значительно медленнее)
.\.venv-local\Scripts\python.exe models.py --profile cpu
```

При resume Ultralytics восстанавливает параметры checkpoint; CLI-профиль не
переписывает оптимизатор и расписание. Следующие запуски создают `ppe52`, `ppe53`
и т. д.; используйте фактический путь, напечатанный в консоли. Метрики и графики:
`runs/detect/ppe5*/results.csv`, `results.png`, confusion matrix, PR-кривые.
На время обучения закройте анализ камер, чтобы освободить видеопамять.

На этом компьютере короткий тест с `workers=2` задержался на первой validation;
переход на `workers=0` и batch 4 сократил весь тест с ~648 до ~39 секунд.
Это измерение запуска на 4 изображениях, не прогноз времени полного обучения.

Объектов очков заметно меньше остальных. После обучения отдельно проверьте
precision/recall очков и перчаток и видеозаписи своих камер. Для улучшения качества
добавляйте размеченные кадры с реальных ракурсов и освещения объекта.
Официальные параметры: [Ultralytics Train](https://docs.ultralytics.com/modes/train/).

## Как работает журнал

- Отдельный поток загружает одну общую модель, последовательно обрабатывая камеры.
  У каждой камеры хранится только последний ожидающий кадр: очередь не растёт.
  Подача на анализ ограничена четырьмя кадрами в секунду на камеру; фактическая
  частота зависит от количества камер и скорости устройства.
- СИЗ сопоставляются с областью конкретного человека, а не со всем кадром.
  Confidence: 0.50 для человека, 0.25 для предметов СИЗ.
- Событие требует нарушения минимум **30 секунд и 5 наблюдений**. Прямые метки
  `NO HELMET`, `NO VEST`, `NO GLOVES`, `NO PPE GLASSES` учитываются при confidence ≥ 0.5.
  Нет подтверждения нарушения или перерыв между наблюдениями больше 3 секунд —
  отсчёт начинается заново. Две камеры не удваивают прошедшее время.
- Одно продолжающееся нарушение сохраняется один раз. Чтобы начать новый эпизод
  того же нарушения, нужно 5 секунд наблюдать соответствующий надетый СИЗ.
  Неизвестное состояние или пропавшая рамка не отменяют защиту от повторов.
- На обрезанных, сильно перекрывающихся и слишком мелких людях отсутствующие
  СИЗ не фиксируются. Минимальная высота человека после масштаба инференса:
  140 px для каски/жилета, 240 для перчаток, 300 для очков.
- Между камерами одной рабочей зоны выполняется приблизительное сопоставление
  по цветам верхней и нижней частей одежды полного силуэта. При однозначном
  совпадении объединяются таймер и защита от повторов. Это не идентификация личности:
  одинаковая форма, освещение и ракурс могут приводить к ошибкам. При неоднозначности,
  отсутствии полного силуэта или в разных зонах треки не объединяются.
  Память сопоставлений действует до 5 минут после последнего наблюдения (максимум
  512 треков); перезапуск программы/перезагрузка модели очищает её.
- Журнал работает и при открытой вкладке событий. Анализируются подключённые
  камеры **текущей страницы выбранной рабочей зоны** (до 9). При смене страницы
  или зоны прежние потоки закрываются. Закрытое приложение мониторинг не ведёт.
- Поиск по камере, зоне и дате; фильтр по СИЗ; страницы по 100 событий; экспорт
  всех подходящих записей в CSV; просмотр фото двойным щелчком.

Снимок содержит рамки, подпись камеры/зоны, время UTC+05:00 (Кызылорда), временный
трек и отсутствующие предметы. База также хранит confidence детекций и SHA-256
весов. Если фото не записалось, событие не добавляется в базу.

**«Не обнаружено» не означает доказанное отсутствие СИЗ.** Размытие, ракурс,
закрытые руки и низкая освещённость могут вызвать ложные события. Геометрическое
сопоставление и временное подтверждение уменьшают их, но не устраняют.
Перчатки учитываются как обнаруженный предмет: наличие перчаток на обеих руках
и правильность ношения всех СИЗ эта модель не удостоверяет.
События помечены **«Требует проверки»**.

Хранение рядом с конфигурацией приложения:

```text
data/events/events.sqlite3          журнал SQLite
data/events/photos/YYYY-MM-DD/*.jpg снимки с подписями
data/events/analysis.log            диагностика, ротация 2 МБ × 4 файла
```

Автоматического удаления снимков нет; размер архива зависит от числа событий.
При переносе журнала копируйте всю папку `events` после закрытия приложения.
Пароли и RTSP-адреса не записываются в события. Настройки камер сохраняются как
раньше в `data/config.json`; старые поля неподдерживаемых модулей сохранены для
совместимости, в окне контроля предлагаются четыре актуальных СИЗ.

## Установка на другом компьютере

Python 3.12 с Tcl/Tk и актуальный драйвер NVIDIA. Из папки проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1 setup
powershell -ExecutionPolicy Bypass -File .\run.ps1 run
```

Перенесите `weights/weights.pt` вместе с `weights/weights.labels.json`.
Проверенная версия RF-DETR зафиксирована: `1.11.2`. Setup устанавливает
PyTorch `2.11.0` / torchvision `0.26.0`, CUDA 12.8. Интернет нужен для установки
пакетов. Приложение работает с локальными весами и не отправляет видеокадры в Roboflow.
Для старых экспериментов YOLO зависимости устанавливаются отдельно из
`requirements-training.txt`.

## Проверки

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1 test
.\.venv-local\Scripts\python.exe -m tests.gui_smoke
.\.venv-local\Scripts\python.exe -m tests.weights_smoke
```

Последние две проверки выполняются явно: первая открывает тестовое окно и
использует временное видео/базу, вторая проверяет реальные `weights.pt`, загрузку
карты классов, поток анализа, рамки и сброс результатов при отключении.
Результаты: `.artifacts/weights-review/worker-smoke.json` и `verified-detections.jpg`.
Для неё нужно одно из существующих локальных изображений `data/ppe5/images/test`.
